# 上流 nanaism/yomiyasu への提案（3.0.0 時点）

フォーク ShortArrow/yomiyasu の方針では上流の既存ファイルを書き換えないため、ここでは案だけを書きます。

## 1. `_touch` を O_NOFOLLOW で開く（scripts/yomiyasu_check.py:618）

`_touch` は `os.O_CREAT | os.O_WRONLY` で開き、そのあと `_chmod` を呼びます。どちらもシンボリックリンクをたどります。
状態フォルダの索引の名前にリンクがあると、POSIX ではリンク先のファイルを作って 0o600 に変えます。
ほかの書き込み（`_mkstemp`、`_place_new_file`）はすでに O_NOFOLLOW を付けているので、そろえる案です。

```python
def _touch(folder: str, name: str) -> None:
    """空のファイルを作る（索引。すでにあればそのまま）。"""
    path = str(Path(folder, name))
    handle = os.open(path, os.O_CREAT | os.O_WRONLY | getattr(os, "O_NOFOLLOW", 0), 0o600)
    os.close(handle)
    _chmod(path, 0o600)
```

- 脅威の筋書き（実際の脅威ではないと見ています。ほかの書き込みとそろえるための案です）:
  - 値を決めるのは check です。名前は時刻と run_id で、run_id は乱数ですが、`start --run-id` で呼び出す側も決められます。
  - 攻撃者が握る経路: 状態フォルダの中に、その名前でリンクを先に置く必要があります。スキルが確認なしで動かせるのは lint と
    check だけで、どちらもリンクを作れません。リンクを作るコマンドは利用者の確認を通るので、通った時点でもっと直接の手段が
    あります。悪意のあるリポジトリが `.yomiyasu/` の下にリンクをコミットしておく経路では、名前に実行時の時刻が入るので
    末端の名前は先に置けません。フォルダ（`.yomiyasu/index` など）をリンクにすれば索引ごと別の場所へ向けられますが、
    それは末端の O_NOFOLLOW では防げません。
  - 握られたら失うもの: POSIX で、リンク先に空のファイルができ、そのファイルの権限が 0o600 になります。中身は書かれず、
    読まれもしません。
- テスト案：POSIX で、索引の名前に、作業フォルダの外を指すリンクを先に置く。そのうえで `_touch` を呼び、OSError（ELOOP）になること、リンク先が作られないことを確かめる。

## 2. `yomiyasu_diff.py`（11,548行）を分ける

- 1ファイルに、段落の組み立て、語の増減、慎重表現、値、出力の整形が同居しています。
- 分け方の案：検出器（「消えた語」「つなぎの増減」など）ごとに、モジュールを1つずつにします。共通の段落の組み立てと出力は、本体に残します。
- 振る舞いを変えない分割は、今あるテストを1つも書き換えずに通すことを条件にします（tidy first）。
- 配布は `skills/yomiyasu/scripts/` に写して行い、CI は写しの一致をファイルごとに見ています。そのため、増えたファイルを CI の `for file in scripts/yomiyasu_*.py ...` に足す必要があります。
